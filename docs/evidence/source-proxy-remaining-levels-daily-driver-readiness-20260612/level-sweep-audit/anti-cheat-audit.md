Scope: existing random 10, 10b, and 10c evidence only. This audit did not generate new prompts and did not patch product code.

## Concern Items

1. A route GO and openable page are still not enough. Failed behavior rows prove static or weak UI can pass earlier pipeline stages.
2. Repair model output often fails the action contract by returning code without a path/action. The rejection is good; the unresolved behavior remains red.
3. Missing behavior contract/probe metadata prevents some repairs from even attempting a model-authored fix.
4. Absence of scaffold/fallback flags is not the same as a complete proof of no hidden tailoring. Treat it as no evidence found, not CLEAN.

## Anti-Cheat Constraints For Any Future Fix

- Keep behavior probes strict.
- Keep route/open/static DOM as non-pass signals.
- Keep one repair attempt unless Britton explicitly approves otherwise.
- Preserve raw transcript, parsed action decisions, workspace diff, behavior probe, repair packet, and repair result.
- Do not add prompt-specific aliases, exact prompt handling, deterministic UI templates, hidden fallback app code, or benchmark answer keys.
