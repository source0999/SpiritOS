# Trace Instrumentation Plan

Goal: improve route/intake and repair traceability without changing stable `behavior-probe.json`, `score.json`, or `receipt.json` schemas.

Preferred approach: add sidecar route trace evidence such as `route_trace.json`, or add fields only to per-prompt trace artifacts generated by the evidence/report layer.

## Needed Fields

| field | purpose | current status |
| --- | --- | --- |
| original_prompt | exact user prompt | present in result rows and traces |
| normalized_prompt | lowercased/normalized prompt used for routing | missing |
| family_candidates | all matched behavior/intake family candidates | missing |
| family_match_reasons | token/rule reasons for candidates | missing |
| standalone_artifact_signals | creation verb, UI noun, disposable hint, no target | missing |
| real_repo_signals | existing/src/component/route/production/fix/update signals | missing |
| explicit_target_path_detected | whether target/path was detected before fallback | partially inferable, not explicit in trace |
| selected_artifact_family | final family or probe id selected | present as family/probe in result rows, incomplete for blocked theme |
| behavior_contract_probe_id | behavior contract probe id | present in per-prompt traces for most, missing/not recorded for final-l3-clean-03 |
| normalized_intent_before_route | intake shape before final route scoring if available | missing |
| normalized_intent_after_route | final task_shape/normalized_intent | present |
| route_decision | GO/NO-GO/EXPECTED-BLOCKED | present |
| route_decision_reason | concise route branch reason | partially present through reason codes, not enough |
| disposable_candidate_true_false | whether resolver considered prompt disposable | missing |
| blocking_reason_if_any | why blocked | present partly in score/receipt reason codes |
| selected_preview_path | preview path | present |
| why_no_preview_if_blocked | no preview reason for blocked route | partially present as `missing_preview_artifact`, should be explicit |

## Current Gaps Exposed By Gate A

- For `cost sharer`, traces show calculator contract success and blocked route, but not that `_resolve_disposable_artifact_create()` missed `sharer/share/fee`.
- For `palette switch`, traces show expected theme behavior but missing probe id and no route reason explaining `switch` vs `switcher`.
- For `secret phrase strength gauge`, traces show password behavior contract success and blocked route, but not that resolver lacked `phrase/passphrase/strength/gauge`.
- Weather and drawing traces show failure buckets, but not enough source-file summary to explain selector/id mismatch without manually inspecting workspace files.

## Non-Breaking Implementation Notes For Gate B

- Do not add required fields to `behavior-probe.json`.
- Do not change score pass/fail semantics.
- Do not change receipt action schema.
- Add route trace fields in evidence/report generation or as an optional diagnostics packet section.
- Preserve existing consumers by making new trace files additive and optional.
