# Anti-Scaffold Rules

These rules apply to all future v0.1 implementation phases.

- No disconnected cognitive architecture.
- Prefer wrappers/adapters over duplicate systems.
- Every module must protect or integrate a real flow.
- Passing unit tests alone do not prove integration.
- Preview endpoints must be used by tests, UI, or evidence reports.
- No "brain metaphor" implementation that does not serve a practical system function.
- Dry-run-only modules must name the later integration requirement.
- Phase closeouts must state which existing SpiritOS/Source Proxy flow is protected, wrapped, or prepared.
- New modules must inspect existing Source Proxy, context, decision, verifier, coding runner, Obsidian, Cartographer, and worker routing code first.
- Fake-green prevention is part of the contract: artifact existence, preview availability, and static rendering are not product PASS.
