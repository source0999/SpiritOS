# Revamp v0.1 Scope

## Purpose

Create a pragmatic cognitive control plane foundation for SpiritOS without starting production refactors or standalone metaphor architecture. v0.1 should establish contracts, previews, verifiers, and dry-run proof before any controlled live proof.

Core loop:

`sense -> understand -> remember -> prioritize -> plan -> choose worker -> act -> verify -> learn`

The brain layer mapping is useful planning language only:

1. Brainstem: health, uptime, service readiness
2. Thalamus: input/context router
3. Sensory cortex: repo/log/browser/file/parser layer
4. Hippocampus: memory, Obsidian read-only context, evidence docs, durable runs
5. Amygdala: risk, urgency, fake-green detection, workflow conflict detection
6. Prefrontal cortex: ARPA planner, permission gates, executive policy
7. Basal ganglia: worker/model selector, cost and capability routing
8. Cerebellum: behavior verifier, tests, screenshots, diff checks, truth labels
9. Motor cortex: safe tool execution, Codex/local/API/handoff adapters
10. Feedback loop: evidence, receipts, learning events, approved memory updates

Implementation must not create over-literal brain parts. Each future module must protect or integrate a real SpiritOS flow.

## Core v0.1

- Phase 0: Safe baseline and plan refinement
- Phase 1: Canonical truth contract
- Phase 2: Read-only Hippocampus memory with Obsidian/evidence docs
- Phase 3: Intake/context router preview
- Phase 4: Risk/permission executive preview
- Phase 5: Worker selector and handoff preview
- Phase 6: Behavior verifier
- Phase 7: Safe execution preview
- Phase 8: Integrated dry-run loop
- Phase 9: Controlled live proof
- Phase 10: Final v0.1 closeout/runbook

## Deferred to v0.2 or Stretch

- Automatic learning loop
- Obsidian write-back
- Multi-lane benchmark execution
- Automatic worker starts
- Advanced model performance memory
- Broad dashboard/UI rebuild
- Autonomous execution beyond preview-gated flow

## Explicit Mentor Refinements

- v0.1 is reduced to the control-plane foundation, not the original full 12-phase build.
- Old Phase 8 Learning is deferred to v0.2/stretch and must not block v0.1 core readiness.
- Old Phase 11 Multi-Lane Benchmark Readiness is deferred to v0.2/stretch and must not be implemented during v0.1 without separate Britton approval.
- Old Phase 12 is slimmed into Phase 10: a lightweight readiness report and operator runbook.
- June 12 false-positive fixtures are carried forward as named requirements for Phase 1.3 and Phase 6.2.
- Existing-system reuse is mandatory before new cognitive modules are created.
- A phase cannot close GO by creating unused classes plus passing isolated unit tests.

## Phase Closeout Rule

Every future phase closeout must explain what real existing flow is protected, wrapped, or prepared. If the work is dry-run-only, the closeout must name the later integration requirement.
