# Source Proxy v0.2 Artifact Repair Intelligence Plan

## Goal

Design the next Source Proxy bridge from truthful artifact diagnostics to limited local repair coaching around Qwen-generated disposable artifacts.

Target flow:

`User prompt -> Intent resolver -> Behavior contract -> Initial generation -> Preview/artifact check -> Browser/product behavior check -> Failure packet -> Limited local repair loop -> Re-test -> Final verdict -> Handoff packet if still failing or out of local scope`

## Non-goals

- Do not patch Source Proxy in this plan packet.
- Do not patch generated benchmark artifacts.
- Do not hardcode answers for calculator, dark theme, habit tracker, notes, password checker, drawing pad, music player, or any specific diagnostic output.
- Do not start providers, API calls, Codex workers, local-model workers, benchmark batches, or hidden background jobs.
- Do not write Obsidian.
- Do not perform git operations.
- Do not broaden this into a full cognitive-control-plane or `/coding` rebuild.

## Current baseline from inspected evidence

The original June 12 diagnostic showed safe disposable file authorship and basic create-routing, but it also used weak usability/product signals. It listed calculator, dark theme, todo, weather, and habit tracker as PASS even though later behavior review found several of those were false positives.

The revamped June 12 diagnostic contains 11 prompts. Its manifest and diagnostic summary list six behavior_truth_label PASS rows: homepage, timer, calculator, dark theme, todo, and weather. The separate browser behavior review checked five of those and corrected three to FAIL: calculator returned `0` for `2 + 3 =`, dark theme changed class without changing computed colors, and habit tracker was static hard-coded content with no controls. Browser-confirmed useful PASS examples are homepage and timer; diagnostic-summary PASS examples still include todo and weather but need durable behavior probes in v0.2. A practical baseline is about 4/11 useful PASS unless future evidence proves otherwise.

v0.1 established the canonical truth contract, behavior fixture contract, permission gates, dry-run control-plane previews, and a controlled timer proof. It did not implement repair.

The requested `source-proxy-general-intelligence-diagnostic-20260612-real-behavior-audit` directory was missing, so v0.2 must not claim evidence from it.

## Major design decisions

- Final PASS requires behavior PASS when behavior is required.
- Behavior contracts are created before generation so verification and repair have stable criteria.
- Failure packets are generic and evidence-driven, not benchmark answer keys.
- Repair is limited, local, and confined to disposable generated artifact workspaces.
- Repair prompts may include observed failure and expected behavior, but not a full hardcoded solution.
- Failed, unsafe, blocked, paid/API, production-file, or out-of-scope work becomes HANDOFF instead of fake PASS.
- Source Proxy should preserve raw transcripts, diffs, receipts, verifier observations, and final canonical labels.

## Acceptance criteria

- Product PASS cannot be produced from runtime GO, file creation, preview opening, static DOM presence, or model self-report alone.
- Required behavior is verified with browser/product probes or remains FAIL/UNVERIFIED.
- Repair attempts are bounded and recorded.
- Repair only touches disposable generated artifact workspaces unless Britton separately approves production-file edits.
- Final output is one of PASS, FAIL, UNVERIFIED, BLOCKED, PARTIAL, NEEDS_FIX, or HANDOFF with evidence.
- Known false positives remain zero in closeout.

## Risks

- The repair loop could overfit to known diagnostic prompts instead of using generic behavior contracts.
- Local Qwen may repeatedly produce plausible UI with broken interactions.
- Missing preview/artifact cases may be misclassified as product failures instead of artifact-readiness failures plus behavior UNVERIFIED.
- Repair could accidentally escape disposable workspaces without strict path guards.
- Final verdict aggregation could reintroduce GO/PASS confusion.

## Stop conditions

- Any requested production Source Proxy patch without explicit approval.
- Any generated-artifact repair outside disposable workspaces.
- Any provider/API/Codex/high-usage escalation without Britton approval.
- Any hidden worker start, background job, Obsidian write, or git operation.
- Any phase boundary reached; Codex must stop and wait for Britton approval before continuing.
