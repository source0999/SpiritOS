# Phase Index

All phases are implementation-later phases. Codex must stop at the end of each phase and wait for Britton approval before continuing.

## Phase 0 - Planning baseline and evidence inventory

Establish the inspected evidence set, missing evidence gaps, current baseline, permission boundaries, and phase checklist.

## Phase 1 - Canonical final verdict cleanup

Normalize route status, artifact readiness, behavior result, repair result, and handoff state into canonical final verdicts.

## Phase 2 - Interactive artifact intent resolver

Classify blunt prompts into app/page/demo/mockup/repo/document/artifact tasks before generation, with notes-app style noun collisions handled as app intent unless the user asks for a document.

## Phase 3 - Behavior contract before generation

Create prompt-specific observable behavior criteria before initial generation and before any repair attempt.

## Phase 4 - Failure packet and repair prompt contract

Turn verifier failures into structured packets that local repair can use without receiving hardcoded full solutions.

## Phase 5 - Limited local repair loop

Allow bounded local repair attempts only inside disposable generated artifact workspaces.

## Phase 6 - Re-test and final verdict integration

Re-run artifact readiness and behavior checks after repair and aggregate the final canonical verdict.

## Phase 7 - Handoff packet for failed or out-of-scope local tasks

Create handoff packets for failed repair, missing local scope, production-file needs, provider/API needs, or permission blockers.

## Phase 8 - Advisory model limitation memory

Record advisory local-model limitations without turning one benchmark into a hardcoded rulebook.

## Phase 9 - v0.2 proof diagnostic rerun plan

Plan the proof rerun against the 11 blunt prompts with identical inputs and explicit behavior checks.

## Phase 10 - v0.2 closeout and next-step packet

Close the v0.2 implementation with evidence, known failures, next recommended phase, and permission-safe next actions.

## Out of scope unless Britton separately approves

- Automatic Obsidian write-back.
- Broad autonomous learning loop.
- Full multi-lane benchmark execution.
- Automatic high-cost API/provider usage.
- Hidden worker starts.
- Broad `/coding` UI rebuild.
- Full repo-wide brain revamp.
