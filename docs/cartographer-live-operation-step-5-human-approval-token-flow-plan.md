## Approval Token Definition

A future human approval token is a human-issued, exact-scope authorization artifact.

An approval token is not self-generated by Cartographer. It is not a queue item, not an event record, not evidence, not a receipt, not a command, and not broad autonomy.

No token can approve action outside its exact scope. No token can grant self-approval. No token can grant limited unattended operation or full auto unless a later explicit package separately proves that authority.

## Required Token Fields

A future approval token must include:

- Operator id.
- Approver id.
- Token id.
- Run id.
- Action type.
- Exact allowed files.
- Exact forbidden files.
- Expiry.
- Rollback instructions.
- Verification instructions.
- Current HEAD.
- Expected dirty tree state.
- Kill switch state.
- Trust tier.
- Human approval timestamp.

Missing fields must fail closed.

## Step 5 Boundary

Step 5 is planning only. It may define token requirements but must not implement a live token flow.

Any future implementation must be separately approved and must remain blocked unless token validation is exact, non-expired, non-self-approved, HEAD-matched, dirty-tree-matched, kill-switch clear, and scoped to allowed paths.
