# 1.1.2 Event Storage Decision

Chosen storage: `data/long_running_tasks.sqlite3`, table `long_running_tasks`, column `causal_events_json`.

Schema:

```json
{
  "event_id": "string",
  "trace_id": "string",
  "task_id": "string",
  "event_type": "invocation|consumer|failure|status_transition",
  "subsystem": "string",
  "consumer_subsystem": "string|null",
  "run_id": "string|null",
  "approval_id": "string|null",
  "status_before": "string|null",
  "status_after": "string|null",
  "changed_state_fields": ["status"],
  "created_at": "iso timestamp",
  "notes": []
}
```

Reason: the task store is already the durable source of long-running apply state. Keeping causal events with the task record preserves the Plan 1 constraint: one thin causal seam, no parallel event store.
