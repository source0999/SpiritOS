## Is the consumer evidence real or fabricated?

This is the subtle part and the answer is **both**, in a way that matters:

- The `task_id`/`trace_id`/`consumer_event_id` values are generated by real Source Proxy functions: `create_plan3_durable_task`, `record_subsystem_integration_result`, `begin_subsystem_integration_invocation`, `finish_subsystem_integration_result` (verified in `source_proxy/tasks/long_running.py` and `source_proxy/decision/mac_integration.py`). So the **causal-trace plumbing is genuinely exercised** — these IDs are not random strings typed by hand.
- HOWEVER, the "work product" that gets consumed downstream is the **hardcoded `PLANS[pid]` string** from the generator, and the "research sources" are the hardcoded `SOURCES[pid]` list. The consumer event proves that *a* work product was recorded-and-consumed in the same trace; it does **not** prove that a model produced that work product, that live search fed it, or that the messy prompt was actually answered by the proxy.

In other words: the consumer-evidence invariant the Plan 3 work was built to enforce ("output cannot look green without a consumed result in the same trace") is satisfied — but it is satisfied by consuming a canned answer. This is exactly the failure mode the runbook warns about in rules 10 ("No stage may claim GO using top-level booleans only") and the closeout rule ("Do not count unconsumed output as PASS" / "Do not count preview/advisory/...metadata-only output as PASS"). The consumption is real; what is consumed is not a real proxy run.

## fake_go_detected assessment

`fake_go_detected` is hardcoded `False` in the generator and is never computed from the work product. Given the fabricated `live_search_used` and the self-asserted PASS, the honest value for the six research prompts is **true**, so this field is itself unreliable.

## Verdict

Trace/consumer evidence: **PARTIAL**.
- IDs are present, same-trace, and produced by real plumbing (not hand-faked).
- But the consumed work product is a pre-written string and the live-search claim that should underpin several records is fabricated.
- `fake_go_detected=false` is not trustworthy (hardcoded, never derived).
- Do **not** treat the consumer-event presence as proof Set A passed; the invariant it enforces is necessary but not sufficient, and here it is satisfied by a canned artifact.
