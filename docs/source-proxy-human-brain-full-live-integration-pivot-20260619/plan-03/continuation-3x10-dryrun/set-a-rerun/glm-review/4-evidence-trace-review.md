## How these IDs are produced (runner)

`latest_consumer()` (runner L99-112) extracts the latest `event_type == "consumer"` event from the durable task's causal events and checks `event.trace_id == trace_id`. The consumer event itself is recorded by `record_subsystem_integration_result(...)` (L484-493) and (for A2/A6) by `record_plan3_consumer_evidence(...)` after `apply_plan3_policy(...)` (L472). This is real Source Proxy plumbing, same as the prior review acknowledged. The trace IDs are freshly generated per task (`create_plan3_durable_task`), not copied from old `set-a/`.

## Caveat — what "consumed" actually proves here

`downstream_consumed=true` proves a consumer event exists on the same trace and that the model response (or policy proof) was recorded into causal state. It does **not** prove the consumed artifact is a *good* work product — it proves plumbing. The prior review's note ("consumption is real while the upstream work is not") no longer applies to provenance (the upstream is now a live model response), but the *quality* of the consumed work is graded by the weak gate in Stage 2, so a "consumed" PASS still says nothing about usefulness.
