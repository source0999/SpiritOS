## Work Product
## Plan for a Small Dashboard for Proxy Run Status

**Recommendation:** Create a simple dashboard displaying the status of long-running proxy tasks, policy checks, and key information from coding operations. This will provide a concise overview of the proxy run without overwhelming the user.

**Research-to-Decision Changes:**
Finding: The `source_proxy/tasks/long_running.py` file indicates the system manages tasks with states like "executing", "blocked", and "queued".
Source: source_proxy/tasks/long_running.py
Decision changed: Prioritize displaying the current state of long-running tasks on the dashboard.
Why this changes the recommendation: This directly addresses the need for an overview of what happened during the proxy run.

Finding: The `src/components/coding/CodingCommandCeCenterShell.tsx` file suggests the system handles coding command center operations, including trial runs and receipt information.
Source: src/components/coding/CodingCommandCeCenterShell.tsx
Decision changed: Include a section on the dashboard to show the status and key details of any coding operations performed during the proxy run.
Why this changes the recommendation: This expands the dashboard's scope to encompass a significant aspect of proxy activity.

Finding: The `source_proxy/tasks/durable_execution.py` file mentions "policy_blocked" and "policy_checking" states, indicating policy evaluation is part of the proxy process.
Source: source_proxy/tasks/durable_execution.py
Decision changed: Incorporate a section on the dashboard to display the status of policy checks and any policy-related outcomes.
Why this changes the recommendation: This ensures the dashboard reflects the broader scope of the proxy run, including important policy decisions.

**Evidence Used:**
- source_proxy/tasks/long_running.py
- source_proxy/tasks/durable_execution.py
- src/components/coding/CodingCommandCeCenterShell.tsx

**Plan:**

The dashboard will have the following sections:

1.  **Long-Running Tasks:** Display a list of currently running, completed, and queued long-running tasks with their current status (e.g., "Executing", "Blocked", "Queued").
2.  **Policy Checks:** Show the status of any policy checks performed during the run, including whether they were "Policy Blocked", "Policy Checking", or successful.
3.  **Coding Operations:** Display information related to any coding operations initiated during the run, such as the status of trial runs and key details from receipt information.

**Limits:**

- No configuration or media mutation information will be included.
- No SpiritFlix mutation details will be displayed.
- The dashboard will not include information related to Plan 4 or Set B/C.
- Fake validation results will not be shown.
- The dashboard will focus on providing a high-level overview and will not include detailed logs or debugging information.
- The dashboard will be kept minimal to avoid overwhelming the user.

**Next Handoff:**

The next step is to define the specific data points to be displayed within each section and to choose a suitable dashboarding tool. This will involve further discussion and potentially collaboration with a frontend developer.
