## Work Product
## Plan for a Small Dashboard for Proxy Run Status

**Recommendation:** Create a simple dashboard displaying the status of the current proxy run, focusing on key information without overwhelming the user. This will include the task being executed, its current state (e.g., executing, blocked, queued), and any relevant details extracted from the task specification.

**Research-to-Decision Changes:**
Finding: The codebase includes components for coding command center shell, handling alerts, backend truth, settings, and usage time.
Source: src/components/coding/CodingCommandCeCenterShell.tsx
Decision changed: The dashboard design should consider displaying relevant data from these components, such as the status of coding tasks or the number of alerts.
Why this changes the recommendation: This suggests the potential for richer information beyond just the core task status, offering a more comprehensive view of the proxy run's context.

Finding: The codebase includes tasks related to long-running operations, policy checking, and durable execution.
Source: source_proxy/tasks/long_running.py
Decision changed: The dashboard should include information about the status of long-running tasks, potentially indicating whether they are blocked, executing, or queued.
Why this changes the recommendation:  Given the presence of long-running tasks, the dashboard needs to account for their potentially extended execution times and various states.

Finding: The `long_running.py` file defines states like "policy_blocked", "executing", and "queued" for tasks.
Source: source_proxy/tasks/long_running.py
Decision changed: The dashboard should visually represent these different task states to provide a clear understanding of the run's progress and any potential roadblocks.
Why this changes the recommendation:  Explicitly displaying these states will improve the user's ability to quickly assess the health and progress of the proxy run.

**Evidence Used:**
- source_proxy/tasks/long_running.py: This file defines the states and logic for long-running tasks, informing the need to display task status.
- src/components/coding/CodingCommandCeCenterShell.tsx: This file indicates the potential for displaying broader context related to coding activities and alerts, suggesting additional data points for the dashboard.

**Plan:**

The dashboard will have the following sections:

1.  **Task Identification:** Display the name of the currently executing task.
2.  **Task Status:** Clearly indicate the current state of the task (e.g., "Executing", "Blocked", "Queued").
3.  **Task Contract Snippet:** Show a concise snippet of the task's deterministic contract to provide context on what the task is intended to do.
4.  **Potential Contextual Information (Optional):** If feasible and not overwhelming, consider displaying a very high-level indicator of coding activity or alert status (drawing from `CodingCommandCeCenterShell.tsx`).

**Limits:**

-   No configuration or media mutation information will be included.
-   No SpiritFlix mutation information will be included.
-   No Plan 4 information will be included.
-   No Set B or C information will be included.
-   No fake validation data will be included.
-   The dashboard will be kept minimal to avoid overwhelming the user.
-   Only information directly related to the current proxy run will be displayed.

**Next Handoff:**

The next step is to define the technical implementation of this dashboard, including the data source and visualization method. This will likely involve integrating with the existing proxy run infrastructure to retrieve the necessary task status information.
