## Work Product
## Plan for a Small Dashboard for Proxy Run Status

**Recommendation:** Create a simple dashboard displaying the status of ongoing proxy runs, focusing on key information without overwhelming the user. This will provide a quick overview of what's happening with the proxy.

**Research-to-Decision Changes:**
Finding: The codebase includes components for coding command center shell, handling alerts, backend truth, settings, and usage time.
Source: src/components/coding/CodingCommandCeCenterShell.tsx
Decision changed: Prioritize including a section in the dashboard to display the status of coding-related tasks, such as whether they are currently running, completed, or encountered errors.
Why this changes the recommendation: This directly addresses the user's need for a comprehensive view of proxy run status by incorporating information about a significant aspect of proxy operations.

Finding: The codebase includes tasks related to long-running operations, policy checks, and durable execution.
Source: source_proxy/tasks/long_running.py
Decision changed: Implement a primary view on the dashboard dedicated to showing the status of long-running proxy tasks, including their current state, progress, and any relevant error messages.
Why this changes the recommendation: This aligns with the core purpose of a proxy run dashboard – to monitor the execution of these long-running processes.

**Evidence Used:**
- source_proxy/tasks/long_running.py
- src/components/coding/CodingCommandCeCenterShell.tsx

**Plan:**

The dashboard will have the following sections:

1.  **Active Proxy Runs:** A list displaying currently running proxy tasks. Each entry will show the task name, its current status (e.g., "Executing", "Blocked"), and a timestamp of the last status update.
2.  **Recent Task History:** A log of recently completed proxy tasks, including their status (success/failure), duration, and any associated error messages.
3.  **Task Details (on selection):** When a user selects a specific task from the "Active Proxy Runs" or "Recent Task History" sections, a detailed view will appear. This view will show the task's contract, acceptance criteria, and any relevant logs or metrics.

**Limits:**

-   No configuration or media mutation information will be included.
-   No SpiritFlix mutation details will be displayed.
-   No Plan 4 or Set B/C data will be shown.
-   Fake validation results will not be part of this initial dashboard.
-   The dashboard will focus on the status of proxy runs and will not include other unrelated data.
-   The initial implementation will be minimal to avoid overwhelming the user.

**Next Handoff:**

The next step is to create a basic UI structure for the dashboard and implement the data fetching logic to retrieve the necessary proxy run status information from the `source_proxy/tasks/long_running.py` file.
