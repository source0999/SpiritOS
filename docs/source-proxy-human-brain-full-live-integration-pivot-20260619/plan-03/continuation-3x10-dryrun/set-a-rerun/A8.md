## Work Product
## Plan for a Small Dashboard Showing Proxy Run Activity

**Recommendation:** Create a simple dashboard displaying the status of ongoing and recently completed proxy runs. This dashboard will focus on key indicators like task status (e.g., "executing", "blocked", "completed") and potentially include information related to coding tasks if relevant.

**Research-to-Decision Changes:**
Finding: The codebase includes modules for coding alerts, backend truth, settings, and usage time.
Source: src/components/coding/CodingCommandCeCenterShell.tsx
Decision changed: Prioritize including a section or widget for coding-related metrics on the dashboard if the user indicates interest.
Why this changes the recommendation: This adds a potential dimension to the dashboard beyond just general proxy run status.

Finding: The codebase utilizes `source_proxy/tasks/long_running.py` for managing long-running tasks with status tracking.
Source: source_proxy/tasks/long_running.py
Decision changed: Implement the display of task status (e.g., "policy_blocked", "executing", "queued") as a core component of the dashboard.
Why this changes the recommendation: This directly leverages existing functionality to provide valuable insights into proxy run activity.

Finding: The `long_running.py` file indicates a `MAX_LONG_TASKS` limit of 50.
Source: source_proxy/tasks/long_running.py
Decision changed: Limit the initial scope of the dashboard to display a manageable number of recent or currently running proxy runs to avoid overwhelming the user.
Why this changes the recommendation: This ensures the dashboard remains "small" and avoids information overload.

**Evidence Used:**
- source_proxy/tasks/long_running.py
- src/components/coding/CodingCommandCeCenterShell.tsx

**Plan:**

1. **Identify Key Status Indicators:** Focus on displaying the current status of proxy runs as tracked by the `long_running.py` module (e.g., "executing", "blocked", "queued").
2. **Display Recent Activity:** Show a list of recent proxy runs, potentially with timestamps and their current status.
3. **Optional Coding Metrics:** If the user expresses interest, include a section displaying relevant coding metrics from `src/components/coding/CodingCommandCeCenterShell.tsx`, such as alert statuses or usage time.
4. **Minimalist Design:** Keep the dashboard clean and easy to understand, avoiding excessive details.
5. **Data Source:** The primary data source for the dashboard will be the status information managed within the `source_proxy/tasks/long_running.py` file.

**Limits:**
- No configuration or media mutation information will be included.
- No SpiritFlix mutation data will be displayed.
- The dashboard will not include Plan 4 or Set B/C data.
- Fake validation data will not be part of the dashboard.
- The initial display will be limited to a reasonable number of recent proxy runs (e.g., the last 10-20).
- No live research sources are available for data integration at this time.

**Next Handoff:**
The next handoff will involve designing the user interface for the dashboard, potentially using a simple HTML/CSS structure or a lightweight dashboarding library. This will be followed by implementing the logic to fetch and display the proxy run status data.
