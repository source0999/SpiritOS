## Duplicate-machinery scan (cross-increment contract: "no duplicate machinery")

Findings:
- **Two status vocabularies** (Plan-gate vs runtime-health) are layered, not duplicated — they live in different artifacts and must stay separated. Action: document the separation in Phase 0.4; no merge.
- **Two "decision" concepts**: advisory route decision (`/v1/decisions/route`) vs execution decision (`/v1/tasks/long-running/*`). These are intentionally split (advice vs apply). Action: do NOT merge; keep the split as the safety boundary.
- **Cartographer level_11_event_ledger / workflow_event_ledger / workflow_state** overlap conceptually with a future causal-event ledger. If Plan 1 introduces a causal-event store, it should REUSE one of these ledger primitives rather than create a new parallel state engine (Phase-boundary assertion: "no parallel state engine"). Action for Plan 1: pick Cartographer's ledger as the single event ledger; do not add a competing one.
- No other duplicate engines detected in the inspected paths.

## Compression-trigger note (feeds Phase 0.7)
The matrix shows the tree already separates advice/apply/status cleanly and already has a supervised-proposal backbone (Cartographer) plus an approval-token + ledger primitive set. Compression opportunity is therefore NOT "delete big modules" — it is "stop any Plan 1 from adding a parallel event/state engine; reuse Cartographer ledger + long-running task ids." This is a consolidation constraint, not a deletion.
