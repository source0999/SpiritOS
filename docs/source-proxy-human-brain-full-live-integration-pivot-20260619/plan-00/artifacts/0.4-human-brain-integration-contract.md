# 0.4 Human-Brain and Integration Contract

Status: `TRUTH_FROZEN_READ_ONLY`. Plan 0 planning task. No source edits authorized.
Purpose: define the operator ("human-brain") role and the integration contract that any future Plan 1 MVI must obey, given the 0.1–0.3 findings.

## Operator role (the human brain)

The operator (Britton) is the sole authority for:
- critical boundaries and plan progression;
- first Obsidian write; first Mac write;
- authority expansion; framework/component adoption; route replacement;
- intentional runtime interruption; irreversible/external action;
- commit/push authority.

The operator is NOT replaced by machinery. "Whole-brain integration" in this packet means: a thin but real invocation→consumer trace through existing supervised machinery, with the operator as the approval boundary. It does NOT mean autonomous execution.

## Integration contract (required for any Plan 1 live GO)

### Required causal identifiers (per review-and-gate-contract.md)
Every live invocation trace MUST carry, in one trace:
- `task_id` — EXISTS today (long-running task).
- `trace_id` — MISSING; must be introduced.
- `invocation_event_id` — MISSING; must be introduced at invocation.
- `consumer_event_id` — MISSING; must be introduced when a downstream consumer observes changed state.
- `consumer_subsystem` — MISSING; must name the real consumer (CodingCockpitShell, verifier, or Cartographer ledger).
- task-state fields changed — the specific status transitions that prove the subsystem is decision-bearing.

### Single source of truth for identifiers
- `task_id` / `approval_id` / `run_id` come from the existing long-running task + central-gate path (0.1.1, 0.2). Reuse them.
- `trace_id` / `invocation_event_id` / `consumer_event_id` / `consumer_subsystem` are NEW. They must be added to the decision-bearing path only (the long-running task engine and its consumers), NOT bolted onto the advisory `/v1/decisions/route` handler (which would create a fake causal surface on a non-decision path).

### No-conflation rule (carried from 0.2)
- Plan-gate verdicts (`GO/NEEDS_FIX/BLOCKED_HUMAN/BLOCKED_ENV`, PARTIAL_GO forbidden) and runtime-health status (`GO/PARTIAL_GO/NO_GO/BLOCKED/UNKNOWN`) are DIFFERENT layers. A live trace MUST NOT derive its plan verdict from the runtime-health `PARTIAL_GO` value. The operator (human brain) and the plan-gate reviewer (Codex) decide plan verdicts from causal evidence, not from health probes.

### Consumer-of-record designation
For the MVI, exactly ONE consumer must be named `consumer_subsystem` per trace. Candidates, in priority:
1. `CodingCockpitShell` (operator surface) — for status transitions the operator observes.
2. Verification result recorder — for apply-path verification transitions.
3. Cartographer event ledger — ONLY if reusing Cartographer as the event store (must not become a parallel state engine).

A Plan 1 increment must pick ONE and prove the consumer actually observed the changed field (consumer event follows invocation event, references the same `trace_id`).

### Authority boundary (no expansion without Britton)
The MVI must NOT:
- enable autonomous git commit/push (Cartographer commit/push endpoints stay hard-blocked);
- perform Obsidian or Mac writes;
- adopt a new framework or component;
- replace the canonical `/coding → CodingCockpitShell → v1 route → Source Proxy handler` route without Britton approval;
- wire runtime-health status into a plan verdict.

## Forbidden fake-GO conditions (must all be false for any live GO)
- code exists / route exists / schema exists / status says available — NOT sufficient;
- packet created / preview success / advisory packet — NOT sufficient;
- fixture/mock success — NOT sufficient;
- unconsumed output (invocation event with no matching consumer event) — NOT sufficient;
- skipped required lane (apply without verification, or advice treated as decision) — NOT sufficient;
- backend substitute output — NOT sufficient.

It is buildable on top of existing machinery (long-running task + central gate + shell/verifier consumer) without authority expansion, framework adoption, or route replacement. The blocking prerequisite remains the missing causal-event identifiers (0.1/0.2). No fake GO.
