# 0.7 Formal Architecture Compression Decision

Status: `PROPOSED — REQUIRES BRITTON APPROVAL`. Plan 0 planning task. This artifact PROPOSES the compression decision; it does not execute it. Per execution-handoff, Plan 1 may be requested only after this decision is Britton-approved.

## Compression question
Given the truth freeze (0.1), health (0.2), matrix (0.3), contract (0.4), MVI feasibility (0.5), and risk (0.6), what is the minimal architectural change that makes a thin-but-real whole-brain integration possible without authority expansion, framework adoption, route replacement, duplicate machinery, or fake GO?

## Findings driving the decision
1. The tree already separates ADVICE (`/v1/decisions/route`) from APPLY (`/v1/tasks/long-running/*` + central gate) from STATUS (runtime health). This separation is correct and must be preserved — NOT compressed by merging advice into apply.
2. A mature supervised-proposal backbone already exists (Cartographer levels 2–14 + approval-token runtime + event ledgers + workflow state). It is deliberately preview/approval-only at the API for git mutation.
3. Real decision-bearing identifiers already exist: `task_id`, `approval_id`, `run_id`.
4. The ONLY structural gap blocking a live GO is the absence of the causal-event pair (`invocation_event_id` + `consumer_event_id` + `trace_id` + `consumer_subsystem`) on the decision-bearing path.

## Proposed compression decision

**Decision CD-0 (proposed): Add a single causal-event seam on the existing decision-bearing path; do not add, merge, retire, or replace any subsystem.**

Concretely:
- ADD a thin causal-event contract (`trace_id`, `invocation_event_id`, `consumer_event_id`, `consumer_subsystem`) to the long-running task apply path and exactly one consumer (default: CodingCockpitShell). Reuse `task_id`/`approval_id`/`run_id`.
- DO NOT merge the advisory route handler into the apply path (preserve the advice/apply safety boundary).
- DO NOT introduce a new event/state engine. If an event ledger is needed, REUSE a Cartographer ledger primitive (`level_11_event_ledger.py` / `workflow_event_ledger.py`) as the single ledger; never run a competing one.
- DO NOT enable autonomous commit/push (Cartographer commit/push endpoints stay hard-blocked).
- DO NOT replace the canonical `/coding → CodingCockpitShell → v1 route → Source Proxy handler` route.
- DO NOT perform Obsidian/Mac writes.

**Why this is "compression":** it reduces the distance to a live GO to a single seam rather than a multi-module rewrite, and it prevents Plan 1 from inflating into parallel machinery. It is consolidation-by-constraint, not deletion. No current module is retired or replaced.

## Alternatives considered and rejected
- **A1: Merge advisory `/v1/decisions/route` into apply path.** REJECTED — destroys the advice/apply safety boundary; creates a fake causal surface on a non-decision path; violates forbidden fake-GO.
- **A2: Build a new whole-brain orchestrator service.** REJECTED — new framework/component (hard stop), parallel state engine (no-duplicate-machinery), authority expansion risk.
- **A3: Enable Cartographer autonomous git mutation as the MVI.** REJECTED — authority expansion; Cartographer is intentionally preview/approval-only; enabling mutation is a separate Britton trust-tier decision outside Plan 1 MVI scope.
- **A4: Retire dormant subsystems to reduce surface.** REJECTED for Plan 0/1 — RETIRE is a separate Britton-approved increment; not warranted by the causal-event gap.

## Compression-trigger evaluation (required before phase close)
Trigger met: a clear consolidation opportunity exists (single causal-event seam) that makes the next plan strictly more capable without adding machinery. The trigger is satisfied in the consolidation direction, NOT in a deletion direction.

## Authority required to enact CD-0
CD-0 itself is a PLANNING decision. Enacting it is Plan 1 implementation work and requires:
- Britton approval of CD-0 (this artifact);
- Codex deep review GO at Plan 0 closeout;

CD-0 does NOT, by itself, authorize any source edit, write, commit, push, or live run.

## Phase 0.7 verdict
PROPOSED compression decision CD-0 is the minimal, safe, no-expansion path to a thin-but-real MVI. It is consistent with all Plan 0 hard stops and the no-duplicate-machinery / no-fake-GO contracts. It is presented for Britton approval. Not enacted.
