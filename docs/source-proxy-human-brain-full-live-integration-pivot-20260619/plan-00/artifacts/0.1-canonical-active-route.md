### The decision-bearing path (where state actually changes)

Real state mutation lives in the long-running task / approval-gate chain:

- `source_proxy/api/long_running_tasks.py` — router prefix `/v1/tasks`:
  - `POST /long-running` → `create_long_running_task` (creates task with status state machine).
  - `POST /long-running/{id}/advance` → `advance_long_running_task`.
  - `POST /long-running/{id}/execute-approved` → `execute_approved_action` (the real apply path).
  - `GET /long-running/{id}` and `/stream` and `/plan` — read + SSE.
  - `POST /long-running/{id}/reject-plan`, `/verification`, `/verify`, `/cancel`.
- `source_proxy/approval/gate.py:54` `execute_approved_action` — delegates to `execute_approved_long_running_task`.
- `source_proxy/tasks/long_running.py:842` `execute_approved_long_running_task` — calls `central_gate_check("apply", run_id=...)` (line 858), re-verifies diff, applies patch, writes audit. Task status transitions: `executing` → `applied_needs_verification` (lines 916, 970).
- `source_proxy/approval/external_gate.py:53` `central_gate_check` — the real central gate. Reads `.gate/state.json`; raises `gate_closed`/`gate_blocked`/`gate_malformed`/`increment_mismatch`/`approval_token_missing` unless state ∈ {`APPROVED_INCREMENT`,`RUNNING_INCREMENT`} with matching `approved_increment` and token. Returns `ExternalGateReceipt` (action, increment_id, run_id, gate_state_before, approval_token_id, checked_at).

This chain IS decision-bearing (failure changes task status and blocks apply). It carries `task_id`, `approval_id`, `run_id`. It does NOT carry `invocation_event_id`/`consumer_event_id`/`consumer_subsystem`.
