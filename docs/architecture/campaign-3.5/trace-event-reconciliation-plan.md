# Trace-event reconciliation plan

The v1.1 names are benchmark target terms, not asserted production events.
Before execution, inventory real `source_proxy/` emissions and map every
benchmark event to a real event, payload fields, semantic-equivalence argument,
missing fields, amendment need, evaluator acceptance, and version. Required
target terms include authenticated acceptance, durable creation,
planner/router decision, coder/terminal disposition, reviewer and verifier
results, evidence envelope, final receipt, cancellation/checkpoint/recovery,
and impossibility/nonmutation events.

Record the approved mapping in
`benchmarks/coder-backend-100/v1.1/trace-event-contract-map.json`. Missing or
ambiguous semantics block execution until a versioned amendment is independently
accepted; task definitions remain immutable and cannot be silently renamed or
weakened.
