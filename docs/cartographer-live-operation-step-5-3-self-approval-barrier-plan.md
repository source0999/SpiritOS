# Cartographer Live Operation Step 5.3: Self-Approval Barrier Plan

status: documentation-only

Status date: 2026-05-22

Current HEAD: `40141f34d27d915503f265efba119673a412354a`

## Purpose

This document defines the planning-only self-approval barrier for future human approval token flow.

Cartographer must never approve itself. A future token flow must require a distinct human approver and must fail closed when the operator, approver, executor, or proposing agent roles collapse into self-approval.

Limited unattended operation is not granted. Full auto is not granted.

## Barrier Rules

Future approval token flow must obey:

- Cartographer cannot create its own approval.
- Cartographer cannot approve its own proposed action.
- Cartographer cannot act as human approver.
- `operator_id` and `approver_id` must be distinct when a future action requires approval.
- Missing approver identity fails closed.
- Ambiguous approver identity fails closed.
- Token generated by the same actor requesting execution fails closed.
- Token generated after execution request without human review fails closed.
- Any self-approval attempt becomes a blocked action finding.

## Human Review Requirement

Human review must be explicit, timestamped, and scoped.

The future approver must be able to see:

- Requested action type.
- Exact allowed files.
- Exact forbidden files.
- Current HEAD.
- Dirty-tree expectation.
- Expiry.
- Rollback.
- Verification.
- Trust tier.
- Kill switch state.

No approval may be inferred from queue storage, event storage, recommendation packets, previous successful dry runs, dashboard presence, or lack of errors.

## Forbidden Self-Approval Patterns

Forbidden patterns include:

- Cartographer signs its own approval.
- Cartographer treats recommendation output as approval.
- Cartographer treats durable queue storage as approval.
- Cartographer treats event records as approval.
- Cartographer treats a missing approver as approval.
- Cartographer treats operator silence as approval.
- Cartographer reuses expired approvals.
- Cartographer expands exact scope after approval.

## Manual Checks

After Step 5.3, manually verify:

- `git diff --check` passes.

- Barrier rules say Cartographer cannot create, sign, infer, or approve its own approval.
- Human review requires explicit timestamped and scoped approval.
- The doc blocks approval inference from queue storage, event storage, recommendations, dry runs, dashboard presence, or lack of errors.
- Limited unattended operation is not granted.
- Full auto is not granted.

## Expected Output

Expected output is this docs-only self-approval barrier plan.

No runtime code, tests, token files, token storage, token validators, approval generation, queue execution, command execution, write authority, live autonomy, `/coding` mutation, package/config mutation, staging, commit, push, merge, stash, checkout, clean, branch, or worktree operation is expected.
